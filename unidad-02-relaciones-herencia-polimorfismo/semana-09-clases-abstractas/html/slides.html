Semana 09 · Unidad 2

Clases abstractas

Contratos que las subclases no pueden ignorar

POO con Python

Objetivos

Al terminar podrás…

  • Declarar una base con abc.ABC y @abstractmethod.
  • Explicar por qué una base incompleta no se instancia.
  • Diseñar contratos claros para las subclases.
  • Elegir entre clase abstracta, interfaz y Protocol.
  • Aplicar un método plantilla y duck typing verificable.

El problema

Una base que no representa nada

p = Personaje("Genérico", 100, 5)
print(p.atacar())   # 5

# El objeto existe, pero no es
# un guerrero, ni un mago, ni un arquero.

Peor aún: si una subclase olvida implementar atacar(), el error aparece en pleno combate.

Queremos que el fallo ocurra al crear el objeto, no tres rondas después.

Sintaxis

ABC + abstractmethod

from abc import ABC, abstractmethod

class Personaje(ABC):
    @abstractmethod
    def atacar(self) -> int:
        """Obligatorio en cada subclase concreta."""
  • ABC activa la maquinaria de abstracción.
  • @abstractmethod marca el método como pendiente.
  • La clase que no implemente todos los abstractos no se puede instanciar.

Código · 1

Estado común y contrato

class Personaje(ABC):
    def __init__(self, nombre: str, vida: int, ataque_base: int):
        self.nombre = nombre
        self.vida = vida
        self.ataque_base = ataque_base

    @abstractmethod
    def atacar(self) -> int:
        """Devuelve el daño del ataque."""

    def recibir_dano(self, cantidad: int) -> None:
        self.vida = max(0, self.vida - cantidad)

recibir_dano() es concreto y se reutiliza; atacar() es la obligación.

Código · 2

Cada subclase cumple el contrato

class Guerrero(Personaje):
    def __init__(self, nombre: str, fuerza: int = 6):
        super().__init__(nombre, vida=120, ataque_base=10)
        self.fuerza = fuerza

    def atacar(self) -> int:
        return self.ataque_base + self.fuerza


class Mago(Personaje):
    def __init__(self, nombre: str, mana: int = 30):
        super().__init__(nombre, vida=80, ataque_base=6)
        self.mana = mana

    def atacar(self) -> int:
        if self.mana >= 10:
            self.mana -= 10
            return self.ataque_base + 15
        return self.ataque_base // 2

Código · 3

El contrato se comprueba al crear

try:
    Personaje("Genérico", 100, 5)
except TypeError as error:
    print(error)
# Can't instantiate abstract class Personaje
# without an implementation for abstract method 'atacar'

class Incompleto(Personaje):
    pass        # sigue siendo abstracta

Incompleto("X", 10, 1)   # TypeError
El error llega antes de usar el objeto. Eso es precisamente lo que buscábamos.

Patrón

Método plantilla

class Personaje(ABC):
    @abstractmethod
    def atacar(self) -> int:
        ...

    def realizar_turno(self, enemigo: Personaje) -> int:
        dano = self.atacar()      # paso variable
        enemigo.recibir_dano(dano)  # paso fijo
        return dano

La base fija el algoritmo; las hijas solo deciden cómo atacar. El flujo no se copia ni se sobrescribe.

Comparación

Abstracta, interfaz y excepción manual

HerramientaQué exige
ABCHerencia explícita + métodos implementados
InterfazSolo firmas; en Python se simula con un ABC lleno de abstractos
ProtocolSolo la forma: que los métodos existan
def atacar(self) -> int:
    raise NotImplementedError("Falta implementar atacar()")

NotImplementedError avisa en ejecución, pero no impide crear el objeto.

Duck typing

Protocol: importa la forma

from typing import Protocol, runtime_checkable

@runtime_checkable
class Curable(Protocol):
    nombre: str
    vida: int

    def curar(self, cantidad: int) -> int:
        ...

No hace falta heredar. Basta con tener los atributos y el método. runtime_checkable habilita isinstance().

La comprobación solo mira que el método exista; no valida los tipos de sus parámetros.

Código · 4

Aceptar cualquier objeto curable

def curar_aliado(objetivo: Curable, cantidad: int) -> int:
    curado = objetivo.curar(cantidad)
    print(f"{objetivo.nombre} recupera {curado} PV")
    return curado

aliados: list[Curable] = [
    Aldeano("Ragnar", 40, 120),
    Mascota("Fénix", 10, 30),
]

Aldeano y Mascota no comparten padre. Comparten comportamiento.

Errores comunes

Lo que rompe el contrato

  • Olvidar ABC: el decorador queda sin efecto y la base se instancia.
  • No implementar todo: el TypeError nombra los métodos pendientes; léelo completo.
  • Llamar a super().atacar() sin cuerpo: devuelve None.
  • isinstance() con un Protocol sin runtime_checkable: lanza TypeError.
  • Interfaz gigante: obliga a implementar métodos que la subclase no necesita.
Una subclase de un ABC puede seguir siendo abstracta. No hay objeto hasta completar todos los métodos.

Ejercicio

Diseña contratos, no copias

  • Nivel 1: Habilidad(ABC) con ejecutar(); crea BolaDeFuego y Curacion.
  • Nivel 2: Protocol Curable y una función curar_equipo() que acepte clases sin padre común.
  • Nivel 3: Arma(ABC) con dano() abstracto y un método plantilla describir().
Reto: demuestra con un try/except TypeError que una subclase incompleta no se puede crear.

Resumen

Cinco ideas para llevarte

  • ABC + @abstractmethod convierten una promesa en obligación.
  • La base incompleta no se instancia: el error llega temprano.
  • El método plantilla fija el flujo y delega los pasos variables.
  • Protocol acepta objetos por su forma, sin herencia.
  • Abstrae para obligar; usa composición para reutilizar sin acoplar.

Semana 08 · Unidad 2

Herencia

Reutilizar lo común sin duplicar código

POO con Python

Objetivos

Al terminar podrás…

  • Distinguir una relación es-un de una relación tiene-un.
  • Crear una clase base y subclases con super().__init__().
  • Sobrescribir métodos y usarlos desde una lista común.
  • Consultar isinstance(), issubclass() y __mro__.
  • Decidir cuándo la composición es mejor que la herencia.

Concepto

Herencia = relación «es-un»

Una subclase hereda atributos y métodos de su base y añade lo propio.

Herencia

Un Guerrero es un Personaje. Comparte nombre, vida y ataque.

Composición

Un Personaje tiene un Inventario. Lo usa, no lo es.

Si no puedes decir «X es un Y» con naturalidad, probablemente no toca heredar.

Sintaxis

La pieza clave: super()

class Guerrero(Personaje):
    def __init__(self, nombre: str, fuerza: int):
        super().__init__(nombre, vida=120, ataque_base=10)
        self.fuerza = fuerza

    def atacar(self) -> int:
        return super().atacar() + self.fuerza
  • class Guerrero(Personaje) declara la herencia.
  • super().__init__(...) inicializa la parte heredada.
  • atacar() se sobrescribe y amplía el comportamiento base.

Código · 1

La base concentra lo común

class Personaje:
    def __init__(self, nombre: str, vida: int, ataque_base: int):
        self.nombre = nombre
        self.vida = vida
        self.ataque_base = ataque_base

    def atacar(self) -> int:
        return self.ataque_base

    def recibir_dano(self, cantidad: int) -> None:
        self.vida = max(0, self.vida - cantidad)

Todo lo que comparten los tres personajes vive aquí una sola vez.

Código · 2

Sobrescribir con una regla propia

class Mago(Personaje):
    def __init__(self, nombre: str):
        super().__init__(nombre, vida=80, ataque_base=6)
        self.mana = 30

    def atacar(self) -> int:
        if self.mana >= 10:
            self.mana -= 10
            return super().atacar() + 15
        return super().atacar() // 2

Mago no copia la inicialización: solo añade mana. El ataque conserva el contrato de la base.

Código · 3

Un bucle, tres comportamientos

equipo: list[Personaje] = [
    Guerrero("Ragnar", fuerza=8),
    Mago("Morgana"),
    Arquero("Lyra", flechas=2),
]

for personaje in equipo:
    dano = personaje.atacar()
    print(f"{personaje.nombre}: {dano} de daño")
No hay ningún if isinstance(...). Cada objeto responde con su propia versión de atacar().

Consulta

¿Qué es este objeto?

g = Guerrero("Ragnar", fuerza=8)

isinstance(g, Guerrero)          # True
isinstance(g, Personaje)         # True
issubclass(Mago, Personaje)      # True
isinstance(g, (Mago, Arquero))   # False
FunciónPregunta
isinstance(obj, Clase)¿El objeto pertenece a esa clase o a una subclase?
issubclass(Hija, Base)¿La clase hereda de la otra?

Orden de búsqueda

MRO: el camino de Python

>>> Guerrero.__mro__
(<class 'Guerrero'>,
 <class 'Personaje'>,
 <class 'object'>)

Cuando llamas a un método, Python lo busca de izquierda a derecha en esa tupla. super() avanza al siguiente eslabón, no necesariamente al padre directo.

object es la raíz de toda clase en Python. Aparece al final de cualquier MRO.

Herencia múltiple

El problema del diamante

class A: ...
class B(A): ...
class C(A): ...
class D(B, C): ...

D.__mro__   # D, B, C, A, object

Python usa el algoritmo C3: A aparece una sola vez y el orden es coherente.

Si B y C llaman a A.__init__() directamente, la base se inicializa dos veces. Usa super() de forma cooperativa.

Diseño

Herencia o composición

class Auto:
    def __init__(self) -> None:
        self.motor = Motor()   # tiene-un

    def arrancar(self) -> str:
        return self.motor.encender()

Errores comunes

Lo que rompe una jerarquía

  • Olvidar super().__init__(): la subclase usa self.nombre y lanza AttributeError.
  • Cambiar la firma al sobrescribir: atacar(self, objetivo) rompe el uso genérico.
  • Heredar por conveniencia: reutilizar un método no convierte al hijo en un caso del padre.
  • Abusar de isinstance(): si preguntas por cada tipo, el polimorfismo no está haciendo su trabajo.
Escribir Atacar con mayúscula no sobrescribe atacar(): crea un método nuevo y el original sigue vivo.

Resumen

Cinco ideas para llevarte

  • La herencia modela es-un; la composición, tiene-un.
  • La base guarda lo común y las hijas añaden o especializan.
  • super() inicializa la base y sigue el MRO.
  • Una lista de la clase base ejecuta el método correcto en cada objeto.
  • __mro__ explica el orden; el diamante se resuelve con C3.

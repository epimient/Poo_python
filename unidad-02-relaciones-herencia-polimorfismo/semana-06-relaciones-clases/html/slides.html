Motivación

Una clase sola no cuenta historias

Personaje Jugador Equipo Partida

Un RPG necesita saber quién controla a qué personaje y en qué equipo juega.

En banca: un cliente tiene cuentas; una cuenta registra transacciones.

Guardar "equipo": "Los Cometas" como texto no permite validar cupos ni contar integrantes.

Concepto

Asociación vs. dependencia

Dependencia

Uso temporal dentro de un método.

def calcular_dano(a, b):
    return a.nivel - b.nivel

No se guarda: termina el método y se olvida.

Asociación

Vínculo estable guardado en un atributo.

class Jugador:
    def __init__(self, pj):
        self.personaje = pj

Sobrevive al método: se puede navegar después.

Multiplicidad

¿Cuántos participan?

TipoEjemploImplementación
1:1Jugador ↔ Personajeatributo personaje
1:NEquipo → Jugadoreslist[Jugador]
N:MJugadores ↔ Partidaslista en cada lado
0..1Jugador → EquipoEquipo | None

La cardinalidad se escribe junto al extremo contrario. Léela en voz alta: «un equipo tiene muchos jugadores».

Navegabilidad

¿Desde dónde puedo llegar?

Jugador → personaje → equipo

Unidireccional: solo existe jugador.personaje.

Bidireccional: además existe equipo.jugadores.

Haz navegable solo lo que usas. Cada dirección extra es información que debes mantener sincronizada.

Código · 1:1

El jugador tiene un personaje

class Personaje:
    def __init__(self, nombre: str, nivel: int = 1) -> None:
        self.nombre = nombre
        self.nivel = nivel

class Jugador:
    def __init__(self, alias: str, personaje: Personaje) -> None:
        self.alias = alias
        self.personaje = personaje  # asociación 1:1

ana = Jugador("Ana", Personaje("Kael", 7))
ana.personaje.subir_nivel()
print(ana.personaje.nivel)  # 8

Se guarda el objeto, no una copia del nombre.

Código · 1:N

El equipo agrupa jugadores

class Equipo:
    def __init__(self, nombre: str, maximo: int = 3) -> None:
        self.nombre = nombre
        self.maximo = maximo
        self._jugadores: list[Jugador] = []

    def agregar(self, jugador: Jugador) -> None:
        if len(self._jugadores) >= self.maximo:
            raise ValueError("Equipo lleno.")
        if jugador in self._jugadores:
            raise ValueError("Ya está en el equipo.")
        self._jugadores.append(jugador)
        jugador.equipo = self  # lado inverso

La lista es privada: nadie la muta por fuera.

Código · coherencia

Retirar sin dejar cabos sueltos

def retirar(self, alias: str) -> Jugador:
    for jugador in self._jugadores:
        if jugador.alias == alias:
            self._jugadores.remove(jugador)
            jugador.equipo = None   # limpiar ambos lados
            return jugador
    raise ValueError("No existe ese jugador.")

@property
def jugadores(self) -> tuple[Jugador, ...]:
    return tuple(self._jugadores)  # vista de solo lectura

Mutarla desde fuera deja jugador.equipo apuntando a un equipo que ya no lo contiene.

Código · N:M

Jugadores y partidas

class Partida:
    def __init__(self, nombre: str) -> None:
        self.nombre = nombre
        self.jugadores: list[Jugador] = []

    def inscribir(self, jugador: Jugador) -> None:
        if jugador in self.jugadores:
            raise ValueError("Ya inscrito.")
        self.jugadores.append(jugador)
        jugador.partidas.append(self)

Cada jugador acumula su historial; cada partida, su plantilla.

En una base de datos esto sería una tabla puente. Aquí son dos listas que se actualizan juntas.

Modelo

UML con cardinalidades

      1              1            1           0..*          1
Jugador ─────────── Personaje    Equipo ─────────────── Jugador
   │          tiene un pj        agrupa 1..3        │
   │                                                │
   │ 0..*                                 pertenece │
   └────────────── Partida ─────────────────────────┘
             *                      *

Un jugador tiene exactamente un personaje y como máximo un equipo.

Jugadores y partidas se relacionan en N:M.

Errores comunes

Lo que rompe el modelo

  • Guardar el nombre del equipo en vez del objeto.
  • Exponer la lista interna y saltarse las validaciones.
  • Actualizar un solo lado de la relación.
  • Permitir duplicados o ignorar el cupo máximo.
  • Declarar como atributo algo que solo era una dependencia.
  • Validar con assert: se desactiva con python -O.

Revisa tu código: si puedes hacer equipo._jugadores.append(x), aún no está encapsulado.

Resumen

Tres ideas para llevarte

  • Asociación = atributo con referencia; dependencia = uso pasajero.
  • Multiplicidad dice cuántos; navegabilidad dice desde dónde.
  • La coherencia se centraliza en métodos: agregar, retirar, inscribir.

La semana 07 separa las relaciones todo-parte: agregación frente a composición y ciclos de vida.
